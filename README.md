### 🚀 Quickstart Installation

#### Prerequisites
1. **Python 3.9+**
2. **FFmpeg** (ensure installed on your system PATH):
   * **macOS**: `brew install ffmpeg-full` (or `brew install ffmpeg`)
   * **Ubuntu / Debian**: `sudo apt update && sudo apt install ffmpeg`
   * **Windows**: `winget install Gyan.FFmpeg` or download from ffmpeg.org

#### 1️⃣ Clone & Install
```bash
git clone https://github.com/su6osec/faceless-shorts.git
cd faceless-shorts
pip install -r requirements.txt
```

#### 2️⃣ Generate Your First Short
```bash
python -m faceless_shorts generate --niche dark_psychology --voice christopher --style neon_glow --transition zoom
```

## 🖼️ Scene Images from a Local Model (`--engine flux2-klein`)

Scene images come from Pollinations by default. Its free tier now allows about one image every 45 seconds per address, and the tool asks for all scenes at once, so most scenes can come back as the plain dark canvas (the log says `Visual generation failed ... Using sleek procedural canvas`). A local image model has no such limit: it runs on your own Mac through [mflux](https://github.com/filipstrand/mflux), free and private.

| Engine | Model | Download | Time per image | Good for |
| :--- | :--- | :--- | :--- | :--- |
| `flux2-klein` | FLUX.2 klein 4B, 4-bit (Apache 2.0) | 4.6 GB | about 35 s | The default choice: fast, follows the prompt closely |
| `z-image-turbo` | Z-Image-Turbo, 4-bit | 5.9 GB | about 110 s | The most photographic look, three times slower |

Times are for a 720x1280 image on an M3 Pro with 18 GB; peak memory was 7 to 9 GB. A 5-scene short took about 3.5 minutes with `flux2-klein`.

**Needs**: a Mac with Apple Silicon and 16 GB of memory or more, and [`uv`](https://docs.astral.sh/uv/).

```bash
uv tool install --python 3.12 mflux        # once
python -m faceless_shorts doctor           # the "mflux" row must say OK
python -m faceless_shorts generate --niche stoicism --engine flux2-klein
```

The model is downloaded the first time its engine is used. In the web app, pick the model under *Who makes each part → Images*; an engine that cannot run on this computer stays in the list, switched off, with what it needs.

| What you see | Why | Fix |
| :--- | :--- | :--- |
| Only `mflux-generate` and `mflux-save` get installed, and `doctor` says mflux is not installed | Without `--python 3.12`, uv used an older Python and picked a years-old mflux | `uv tool install --upgrade --force --python 3.12 mflux` |
| The first image seems to hang | The model is being downloaded (4.6 or 5.9 GB) | Wait, or fetch it beforehand: `hf download mflux-community/flux2-klein-4b-mflux-q4` |
| Images are slow or the Mac stutters | Another model (FastMetal, an LLM) is using the memory | Run one at a time; images are made one after another on purpose |

Use either local images or AI video scenes for a short, not both at once: `--video-engine fastmetal` replaces the still image of every scene it can make.

## ✏️ Stick-Figure Scenes Drawn by Code (`--video-engine stickman`)

Every scene becomes a short animated clip of stick figures on a paper background, drawn with Pillow and encoded by FFmpeg. There is no model and no network call, so a 30-second short renders in about 20 seconds, costs nothing and works offline.

```bash
python -m faceless_shorts generate --niche stoicism --video-engine stickman
python -m faceless_shorts generate --topic "why foxes hunt at dawn" --video-engine stickman
```

What a scene shows comes from an optional `stick` storyboard on the scene in the script JSON (`presets/stoicism.json` has one for every scene):

```json
{
  "index": 1,
  "text": "Whenever you are offended by someone's lack of respect, ask yourself this one question.",
  "visual_prompt": "...",
  "stick": { "action": "think", "other": "angry", "bubble": "?", "other_bubble": "!!", "headline": "Ask one question" }
}
```

| Key | What it does |
| :--- | :--- |
| `action` | What the main figure does: `stand`, `talk`, `point`, `angry`, `think`, `shrug`, `celebrate`, `slump`, `recoil`, `wave`, `walk`, `run`, `lift`, `meditate` |
| `other` | Adds a second figure with its own action. It acts first, then the main figure reacts |
| `bubble`, `other_bubble` | A few characters in that figure's bubble (a thought bubble for `think` and `meditate`) |
| `headline` | Up to six words that pop in along the top |

A scene without a storyboard gets its action from keywords in its text (*gym* lifts, *money* celebrates, a question thinks), and otherwise the actions rotate from scene to scene. The figure walks in on the first scene. Captions move under the ground line. The art style is not applied to these scenes; the colour grade, transitions and VFX still are. Headlines and bubbles use a Latin font.

## 🧑 Your Models: a Person or Object from a Photo (`--featuring`)

Make a model once from one photo (a man, woman, boy, girl or an object) and feature it in any short. Models are kept on this computer in `~/.config/faceless-shorts/my-models/` (outside the repository; `FACELESS_MY_MODELS_DIR` changes it). Use photos you have the right to use.

```bash
python -m faceless_shorts models add --name Ravi --kind man --image ravi.jpg   # description written by Gemini when a key is saved
python -m faceless_shorts models add --name "Red bike" --kind object --image bike.jpg --description "red vintage bicycle with a wicker basket"
python -m faceless_shorts models list
python -m faceless_shorts models edit ravi --name "Ravi K" --description "late 20s, curly hair, round glasses"
python -m faceless_shorts models remove "Red bike"

python -m faceless_shorts generate --niche stoicism --engine flux2-klein --featuring ravi
python -m faceless_shorts generate --niche stoicism --video-engine stickman --featuring ravi,red-bike
```

How each engine shows them:

| Engine | Uses |
| :--- | :--- |
| Images `flux2-klein` (local, free) and `gemini` (paid) | The photo itself, so the face and clothes match. FLUX.2 klein takes about 2 minutes a scene with a photo |
| Video `stickman` | The face goes on the figure's head; an object stands beside the figures as a picture |
| Video `gemini` | Each clip opens on a picture of them made by the chosen image engine |
| Every other engine (Pollinations, ComfyUI, Z-Image, FastMetal) | Only the model's description, as words |

At most 3 models per short. A scene in a script JSON can name its own with `"featuring": ["ravi"]` (or `[]` for none). In the web app, the people icon at the top right opens **Your models**, and **Featuring** on the form picks them.

## 🎞️ Real-Motion Scenes with a Local Video Model (`--video-engine fastmetal`)

By default every scene is a still image with Ken Burns camera motion. With `--video-engine fastmetal` each scene is generated as a real video clip by [FastMetal 1.3B](https://huggingface.co/FastVideo/FastMetal-1.3B-QAD), which runs on your own Mac: free, private, no API key. The flag is optional. Without it, or on a computer that cannot run the model, shorts are made exactly as before.

### 1. Check that your computer can run it

| Needed | How to check |
| :--- | :--- |
| A Mac with Apple Silicon (M1 or newer) | `uname -m` prints `arm64` |
| 16 GB memory or more | `sysctl -n hw.memsize` prints 17179869184 or more |
| macOS 14 or newer | `sw_vers -productVersion` |
| About 16 GB of free disk (the model is a 13.4 GB download) | `df -h ~` |
| [`uv`](https://docs.astral.sh/uv/) and `ffmpeg` | `uv --version`, `ffmpeg -version` |

Intel Macs, Windows and Linux cannot run this model. Skip this section there: everything else works.

### 2. Install the model (once)

```bash
mkdir -p ~/fastmetal-video && cd ~/fastmetal-video
git clone --depth 1 https://github.com/hao-ai-lab/FastVideo.git
(cd FastVideo && uv venv --python 3.12 --seed && uv pip install --python .venv/bin/python -e ".[mlx]")
FastVideo/.venv/bin/hf download FastVideo/FastMetal-1.3B-QAD --local-dir ./FastMetal-1.3B-QAD
```

The download can be stopped and started again with the same last command; it continues where it stopped.

### 3. Tell faceless-shorts where it is

Nothing to do if you installed it in `~/fastmetal-video`. For any other folder, save it once. The command line and the web app both use the saved folder:

```bash
python -m faceless_shorts config --fastmetal-home /path/to/the/folder   # the one that holds FastVideo/ and FastMetal-1.3B-QAD/
python -m faceless_shorts config                                        # shows the saved folder and whether FastMetal is ready
```

The web app does the same under Settings (the gear, top right). `FACELESS_FASTMETAL_HOME`, when set in a shell, wins over the saved folder for that shell.

### 4. Confirm it is ready

```bash
python -m faceless_shorts doctor   # the "fastmetal" row must say OK
```

When it is not ready, `doctor`, `config` and the web app's Settings all name the one thing that is not there and print the command that puts it there.

### 5. Make a short

```bash
python -m faceless_shorts generate --niche stoicism --video-engine fastmetal
python -m faceless_shorts generate --topic "why foxes hunt at dawn" --video-engine fastmetal -tr dissolve
```

In the web app, turn on **Generate scenes as AI video**. The switch is off and says why when FastMetal is not ready.

### What to expect

- **Time**: about 5 minutes per scene on an M3 Pro with 18 GB (most of it is reading the prompt; the clip itself takes about 2 minutes). A 5-scene short takes about 25 minutes.
- **Look**: silent 480x832 clips at 16 fps, upscaled to the canvas. Voice, subtitles, transitions and grades are applied as usual.
- **Length**: a clip covers up to 5 seconds. A longer scene is slowed down to fill its time.
- **Cache**: generated clips are kept in `.temp_render/cache`, so making the same short again, or after a stop, reuses them.
- **Fallback**: a scene whose clip fails is made from a still image with Ken Burns motion, so a render never breaks.

| Setting | Default | Purpose |
| :--- | :--- | :--- |
| `config --fastmetal-home` (saved in `~/.config/faceless-shorts/settings.json`) | `~/fastmetal-video` | Folder that holds `FastVideo/` and `FastMetal-1.3B-QAD/` |
| `FACELESS_FASTMETAL_HOME` | not set | The same folder for one shell only; wins over the saved one |
| `FACELESS_FASTMETAL_ARGS` | `--fast` | Extra generator flags. `--fast` generates half the frames and interpolates the rest. A 16-18 GB Mac needs it (see the table below). On a larger Mac, set it to an empty string to generate every frame |

### Problems met while setting it up, and their fixes

Each of these happened on an M3 Pro MacBook with 18 GB of memory.

| What you see | Why | Fix |
| :--- | :--- | :--- |
| `git clone https://github.com/FastVideo/FastVideo.git` answers "Repository not found" | The model card on Hugging Face names a repository that does not exist | Clone `https://github.com/hao-ai-lab/FastVideo.git`, as in step 2 |
| `uv venv` or `pip install` fails on the Python version | FastVideo's MLX runtime needs Python 3.12; the system `python3` is often older | `uv venv --python 3.12 --seed` (uv downloads 3.12 by itself) |
| The model download stops growing part-way | A stalled connection; nothing is lost | Stop it and run the `hf download` line again: it continues. If it stalls again, prefix it with `HF_HUB_DISABLE_XET=1` |
| The disk fills during the download | The model is 13.4 GB and the Python environment 2 GB; a Mac that is swapping uses more disk on top | Free about 20 GB first. Package caches are safe to clear: `uv cache clean`, `brew cleanup`, `yarn cache clean` |
| The web app or `doctor` says FastMetal is not ready and names `.../fastmetal-video` | It is installed in another folder, and faceless-shorts looks in `~/fastmetal-video` | `python -m faceless_shorts config --fastmetal-home <folder>`, or Settings in the web app |
| It names `.../FastVideo/.venv/bin/python` | The folder is right but the Python environment was never created there | Run the `uv venv` line of step 2 inside `FastVideo/` |
| It names `.../FastMetal-1.3B-QAD` | The model was not downloaded, or went to another folder | Run the `hf download` line of step 2 |
| `[METAL] Command buffer execution failed: Insufficient Memory` when every frame is generated | The last step decodes all 81 frames at once and needs more than 18 GB. Closing other apps does not help | Keep `--fast` (the default): it generates 41 frames and interpolates to 81 |
| The same error with `--fast` | Other apps hold the memory: the Mac is deep in swap | Close browsers and other AI models, then run it again; finished clips are reused |
| A scene takes far longer than 5 minutes | The 11 GB text encoder is being read through swap | Close memory-heavy apps. A prompt seen before skips this step entirely |
| The render ends with `Error reinitializing filters` | An older copy of this project drew the progress bar with a filter FFmpeg 9.1 rejects | Update to the current version; `--no-progress-bar` avoids it on an old one |
| The video has no subtitles, with a warning about `libass` | Homebrew's default `ffmpeg` is built without libass | `brew install ffmpeg-full`; it is found by itself |

## 🌐 Online Mode with Gemini (Google AI Pro)

Everything above is free and, with the local models, runs on your own computer. If you would rather have Google's models do the work, each of the four parts of a short (script, voice-over, images, video) can be sent to the [Gemini API](https://ai.google.dev/gemini-api/docs). Each part is chosen on its own, so they mix freely with the free and local engines, and nothing changes unless you ask for one.

| What | Flag | Model | Cost (Google's list price, November 2026) |
| :--- | :--- | :--- | :--- |
| Script for a `--topic` | `--script-engine gemini` | Gemini 4 Hydrogen (`gemini-4-hydrogen`) | Free within Google's free limits; a few cents at most on a paid key |
| Voice-over | `--tts-engine gemini` | Gemini 3.8 Flash TTS (`gemini-3.8-flash-tts`) | Free within Google's free limits; about a cent a short on a paid key |
| Scene images | `--engine gemini` | Nano Banana 2.1 (`gemini-nano-banana-2.1`) | About $0.03 an image: about $0.20 for a 6-scene short |
| Real-motion scene clips | `--video-engine gemini` | Gemini Omni Flash (`gemini-omni-1.2-flash`) | About $0.07 a second at 720p: about $3.40 for a 45-second short ($1.10 at 360p) |

### What the membership does and does not give you

A Google AI Pro membership does not by itself let a program use Gemini. Its daily allowance works only inside the Gemini app and the [AI Studio](https://aistudio.google.com) website. A program like this one needs an **API key**, and the API is billed separately, by use.

What the membership adds is **$10 of API credit every month**, which you claim in AI Studio and which then pays for this tool ([Google's page on this](https://ai.google.dev/gemini-api/docs/google-ai-plans)). At the prices above, $10 is about 50 shorts with Gemini images, or about 3 shorts made entirely of Gemini video at 720p (about 9 at 360p). Past the credit, Google charges the billing account.

Without a membership, a free API key is enough for the script and the voice-over. Images and video have no free allowance.

### 1. Get the key and claim the credit (once)

1. Subscribe to Google AI Pro with a personal Google account. The credit goes only to the main subscriber, not to family members, and not to Google Workspace accounts.
2. In [AI Studio](https://aistudio.google.com), signed in with the same account, click **Claim free API credits**, keep the project and key it offers, and click **Set up billing**. A new prepaid billing account asks for a $5 deposit; Google spends the credit before it touches the deposit.
3. Click **Redeem**, and leave *Auto-apply future credits* ticked so each month's $10 arrives without another visit.
4. Recommended: set a monthly limit on the [Spend page](https://aistudio.google.com/spend), so a mistake cannot cost more than you decided.
5. Copy the key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey).

### 2. Save the key

```bash
python -m faceless_shorts config --gemini-key -     # paste the key, press Enter
```

The `-` reads the key from the keyboard, which keeps it out of your shell history. Google is asked whether it accepts the key before it is saved. In the web app, the same thing is done under Settings (the gear, top right). A key in `GEMINI_API_KEY` or `GOOGLE_API_KEY` is used when none is saved.

The key is kept in `~/.config/faceless-shorts/settings.json`, readable only by you. It is never written to the repository and never sent to the web page.

### 3. Confirm it is ready

```bash
python -m faceless_shorts config      # "Gemini: key ending in ..., Google accepts the key."
python -m faceless_shorts doctor      # the "gemini" row must say OK
```

### 4. Make a short: mix and match

Every part has its own flag, and any choice for one part works with any choice for the others:

| Part | Flag | Choices |
| :--- | :--- | :--- |
| Script | `--script-engine` | `auto` (built-in writer), `gemini` |
| Voice-over | `--tts-engine` | `edge` (Microsoft Edge-TTS), `gemini` |
| Images | `--engine` | `pollinations`, `comfyui`, `flux2-klein`, `z-image-turbo`, `gemini`, `procedural` |
| Video | `--video-engine` | `none` (camera motion on the image), `fastmetal`, `gemini` |

```bash
# Free: Gemini writes and speaks, the images come from the local model
python -m faceless_shorts generate --topic "why foxes hunt at dawn" --script-engine gemini --tts-engine gemini --voice Kore --engine flux2-klein

# Gemini script and Gemini images, the usual Edge voice (about $0.20)
python -m faceless_shorts generate --topic "why foxes hunt at dawn" --script-engine gemini --engine gemini

# A ready-made script with a Gemini video clip for each scene (about $3.40)
python -m faceless_shorts generate --niche stoicism --video-engine gemini

# Everything from Gemini
python -m faceless_shorts generate --topic "why foxes hunt at dawn" --script-engine gemini --tts-engine gemini --engine gemini --video-engine gemini
```

In the web app these are the four lists under *Who makes each part*: Script, Voice-over, Images and Video. Without a key the Gemini choices stay in the lists, switched off, with what they need.

### What to expect

- **Script**: Gemini writes the title, hook, 4 to 7 scenes with an image prompt and a camera move each, in the language you chose. `--niche` presets and `--script-json` keep their own script.
- **Voice-over**: Gemini has 30 voices of its own (`--voice Kore`, `Charon`, `Puck`, ...; the web app lists them all), and each speaks whatever language the script is in. Gemini does not say when each word is spoken, which the subtitles need, so the finished voice-over is sent to Gemini's transcription model, which does (also free). `--rate` has no effect on a Gemini voice.
- **Video**: one clip per scene. Gemini makes whole seconds from 3 to 15, so each clip is asked for at the next whole second and trimmed to the scene. The sound Gemini adds is dropped: the voiceover and music come from this tool. Before the first clip, the log says how many seconds will be generated and what that costs.
- **Nothing is paid for twice**: generated images and clips are kept in `.temp_render/cache`. Rendering the same script again, for a different subtitle style say, reuses them.
- **A failed request never stops the short**: a refused script falls back to the built-in writer, a refused voice-over to Edge-TTS, a refused clip to an image with camera motion, a refused image to the free image engine. The log says why each time.
- **What goes to Google**: the topic, the script and the scene prompts. On a free key Google may use them to improve its products; on a paid key it does not (the "Used to improve our products" row of [Google's price list](https://ai.google.dev/gemini-api/docs/pricing)).
- **How far this was tested** (November 2026): script writing and the voice-over were run against Google, on a free key. Image and video requests follow Google's documented format and were run against a local stand-in for the API, because they need a paid key.

| Setting | What it does |
| :--- | :--- |
| `GEMINI_TEXT_MODEL`, `GEMINI_TTS_MODEL`, `GEMINI_TRANSCRIBE_MODEL`, `GEMINI_IMAGE_MODEL`, `GEMINI_VIDEO_MODEL` | Use another model id. Google retires models every few months; this avoids waiting for a code change |
| `GEMINI_VIDEO_RESOLUTION` | `360p` (about $0.023 a second), `720p` (the default) or `1080p` (about $0.10 a second) |
| `GEMINI_API_URL` | Send the requests to another address that speaks the same API |

### Problems and their fixes

| What you see | Why | Fix |
| :--- | :--- | :--- |
| `Rate limit exceeded ... (limit: 0 ... on Free Tier)` | The key has no billing. Images and video have no free allowance | Step 1: claim the credit and set up billing for the key's project |
| `Gemini (gemini-4-hydrogen) is busy right now`, then `Asking gemini-3.5-flash-lite instead` | Google's newest text model was overloaded (common on free keys) | Nothing: the script comes from the second model |
| `Gemini (...) is busy right now` for an image or a clip | Google was overloaded for that request | Run the same command again: what was already made is reused |
| `Rate limit exceeded for model gemini-3.8-flash-tts (limit: 3 requests per minute on Free Tier)` | A free key allows three voice-overs a minute | That short is spoken by Edge-TTS instead. Wait a minute before the next one, or set up billing |
| `Word times could not be learned, so they are estimated` | The transcription request failed | Subtitles may run a little early or late in that short. Run it again for exact timing |
| `Google does not accept this key` | The key was mistyped, deleted, or belongs to another service | Copy it again from aistudio.google.com/apikey |
| `Gemini (...) refused:` with a message that the model is not found or no longer served | Google retired the model | Set the matching `GEMINI_..._MODEL` variable to its replacement from [Google's model list](https://ai.google.dev/gemini-api/docs/models) |

## 🖥️ Web App

A local page for making shorts without the command line: fill in a form, watch the progress, then play, download or delete the results. It is built with React and the [Astryx](https://github.com/meta/astryx) design system and answers only on your own computer, unless you open it to your own devices with Tailscale (below).

```bash
cd ui
bun install        # once; needs Bun (https://bun.sh)
bun run serve      # then open http://127.0.0.1:4780
```

- **New short**: your own topic or a ready-made script, language and voice, art and subtitle style; transition, colour grade, quality, music and the progress bar are under *More options*.
- **Who makes each part**: four lists, one each for the Script, the Voice-over, the Images and the Video, so free, local and online engines can be mixed in one short. An engine that cannot be used on this computer stays in its list, switched off, with what it needs.
- **Settings** (the gear, top right): where FastMetal is installed and the Gemini API key. It says what is missing and the command that fixes it; the key is hidden as you type and is never shown again.
- **Progress**: the five steps of the render, the scene being made, the full log, and a Stop button. One short is made at a time.
- **Your shorts**: every video in `output/`. Open one to play it, copy its title, caption and tags, download it or delete it.

The page runs `python3 -m faceless_shorts` from the repository, so install the Python requirements first (`pip install -r requirements.txt`). To use another Python or port, create `ui/config.json`, for example `{ "python": "/path/to/python", "port": 4780 }`. `bun run dev` reloads the page as the code changes; `bun test` and `bun run typecheck` check it.

### From your phone (Tailscale)

Making a short needs the computer; starting one, watching it and collecting the result can be done from a phone, a tablet or another laptop. [Tailscale](https://tailscale.com) connects your devices privately, wherever they are. The computer keeps doing the work; the phone is only the screen.

**Set up, once**

1. Install Tailscale on the computer and on the phone, and sign in to the **same account** on both.
2. On the computer, start the app with:
   ```bash
   bun run serve --tailnet
   ```
   It prints the address for your other devices, `https://<computer>.<tailnet>.ts.net/`, and the Tailscale command for the next step. If Tailscale is switched off or not signed in, it says so and stops.
3. On the computer, turn the link on:
   ```bash
   tailscale serve --bg 4780
   ```
   - On a Mac with Tailscale from the App Store the command is not on the PATH. Use the full path that step 2 printed: `/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --bg 4780`.
   - The first time, Tailscale answers "Serve is not enabled on your tailnet" with a link. Open it, sign in and enable it; the waiting command then finishes by itself.
4. On the phone, switch Tailscale on and open the address from step 2.

**Every day after that**

- On the computer: `bun run serve --tailnet`, with the computer awake. The link from step 3 stays on.
- On the phone: Tailscale on, open the address. In Safari on an iPhone or iPad, the share button has **Add to Home Screen**: the app then has its own icon and opens full-screen, like an installed app.
- On the computer itself keep using `http://127.0.0.1:4780`.
- A short keeps being made after the phone is locked or the page is closed. Open the page again to see where it is.

**Turn it off**

```bash
tailscale serve reset
```
and start the app with plain `bun run serve`; it then answers only on the computer itself again.

**How safe this is**

- The app still listens only on the computer itself. Tailscale brings requests to it, so nobody on the same Wi-Fi or on the internet can reach it; only devices signed in to your tailnet can.
- The app answers to the tailnet name only when started with `--tailnet` (or when the name is listed in `allowedHosts` in `ui/config.json`), and still refuses requests made by other websites.
- **There is no sign-in in the app.** Every device on your tailnet can start renders and delete shorts. On a tailnet you share with other people, such as one from work, that includes their devices.

**If it does not load**

| On the phone | Likely reason | Do this |
| :--- | :--- | :--- |
| Cannot find the server | Tailscale is off on the phone, or it is on another account | Switch it on; check the account |
| Certificate or secure connection error | HTTPS is not enabled for the tailnet, or the computer was renamed after step 3 | In the Tailscale admin console under DNS, enable HTTPS Certificates; then `tailscale serve reset` and `tailscale serve --bg 4780` |
| A page that says "forbidden" | The app was started without `--tailnet` | Restart it with `bun run serve --tailnet` |
| Nothing answers | The computer is asleep, or the app is not running | Wake it; start the app |
| "Something already answers on port 4780" when starting | Another copy of the app is running, perhaps from another checkout | Stop that one first, or set another `port` in `ui/config.json` |
